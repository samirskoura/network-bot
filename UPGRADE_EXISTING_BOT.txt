Single-account bot: up to 80 Creative edits per check
Revision: fresh status checks and conditional headline edits (2026-09-12)

This full package contains the complete single-account bot and its helpers.
For an existing bot, the two required replacements are the Python worker and
the active workflow. The package has not been applied to GitHub.

1. Allow the active workflow to finish before uploading the update. Disable
   scheduled starts temporarily with BOT_ENABLED=false if needed.
2. Download this ZIP again to get the latest safety revision. Replace
   snap_headline_bot.py in your existing GitHub repository with the file
   of the same name in this update. If you deleted it, upload it to the main
   repository folder beside state_crypto.py.
3. Open your EXISTING workflow file in .github/workflows. If yours is named
   samir-bot.yml, keep that filename. Replace its content with the supplied
   snapchat-headline-editor.yml content. Do not add a second workflow. If you
   already installed the supplied 80-limit workflow, only the Python file
   needs replacing for this safety revision.
4. Keep your existing Secrets, Variables, headline_pool.txt,
   blocked_headline_hashes.txt, state_crypto.py, requirements.txt and
   state.json.enc. Keep STATE_ENCRYPTION_KEY unchanged.
5. Run target_1, run_mode=test, max_updates=80, monitoring=one_check.
   Confirm the log says max_updates_per_check=80 and the intended squad count.
   If candidates are available, the log must also say:
   Safety protection enabled: fresh linked-Ad checks and conditional Creative PATCH.
6. First run target_1, run_mode=live, max_updates=1, monitoring=one_check.
   This verifies the conditional PATCH on your account, which test mode cannot
   exercise. After it succeeds and encrypted state is saved, you can select
   max_updates=60 or 80 and monitoring=overnight.
7. Restore BOT_ENABLED=true only if you previously used scheduled starts.

The limit is TOTAL across all selected Ad Squads in ONE Ad Account per check.
It is a ceiling, not a guaranteed edit count: rejected/disapproved status,
review waiting, shared-Creative protection and fresh-headline validation
still determine eligibility. This is not a per-Creative attempt limit.

Status protection in this revision:
- Only a DISAPPROVED Creative whose linked live Ads are all REJECTED and all
  inside the selected Ad Squads can pass the checks.
- APPROVED, PENDING, PENDING_REVIEW and unknown statuses block the edit.
  Pending items are checked again on later cycles and can become eligible
  only after a confirmed rejection.
- The bot refreshes the complete account Ad list before each edit to discover
  shared Creatives, then re-reads each linked Ad and the Creative.
- An approval observed for a selected Creative or its linked Ad is remembered
  in state so that Creative remains protected on future runs.
- The PATCH first tests review_status=DISAPPROVED and the exact old headline,
  then replaces only the headline. It never retries without those conditions.
- Failed, incomplete or ambiguous API responses stop processing. An uncertain
  PATCH keeps its saved reservation to prevent another automatic edit.
- No Ads, budgets, bids, targeting or campaign settings are directly updated.

Snapchat documents that editing a shared Creative affects every linked Ad.
The linked-Ad reads and Creative PATCH are separate requests: Snapchat's
documentation does not provide a transaction that checks all linked Ads and
edits the Creative atomically. These guards reduce the risk of concurrent
status/link changes; an absolute guarantee against such changes is not possible.
The conditional status/headline tests apply to the Creative itself. If Snapchat
rejects a test or its field path, processing stops; do not remove the tests.

OpenAI generation is split into requests of at most 30 Creatives; 80 candidates
needing generation use batches of 30, 30 and 20. Combined suggestions still
pass the existing global duplicate checks before edits.

Manual input defaults to 80. Automatic scheduled starts and the Python fallback
default remain 30; they are not automatically raised by this update.
The monitor waits 60 seconds AFTER each completed check. Larger checks take
longer, especially with the added status reads, so checks do not start exactly
every 60 seconds.

If you have independently changed the bot code since the supplied version,
merge all changes in this Python file into your customized version, including
the fresh checks and conditional PATCH. Raising the limit alone does not add
these protections.

Validation: local simulations only; no real Snapchat edits or OpenAI requests
were made during this update.
